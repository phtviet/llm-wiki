## Training fundamentals
- [[pre-training]] -- training a model from scratch with randomly initialized weights
- [[post-training]] -- training after pre-training, conceptually the same as finetuning
- [[dataset-engineering]] -- curating, generating, and annotating data for training and adaptation
- [[model-development]] -- AI engineering stack layer covering modeling/training, dataset engineering, and inference optimization

- [[language-model]] -- encodes statistical information about language; completion-based, split into masked and autoregressive types
- [[token]] -- basic unit a language model operates on; characters, words, or word-pieces
- [[masked-language-model]] -- predicts missing tokens using both preceding and following context, e.g. BERT
- [[autoregressive-language-model]] -- predicts the next token from preceding context; today's dominant generative approach
- [[self-supervision]] -- infers labels from input data itself, overcoming the data-labeling bottleneck to scale training
- [[foundation-model]] -- large-scale, general-purpose model built on many modalities, adaptable to a wide range of downstream tasks
- [[multimodal-model]] -- model that conditions generation on more than one data modality, e.g. text and images
- [[usefulness-threshold]] -- the quality/latency/cost/fairness bar an AI product must clear before shipping to customers
- [[milestone-planning]] -- planning how to reach a product's goals, accounting for the last-mile challenge from demo to product
- [[competitive-advantage]] -- technology, data, and distribution as the three sources of competitive advantage in AI, and how startups can out-compete incumbents
- [[success-metrics]] -- defining business-impact metrics to measure whether an AI application succeeds
- [[ai-engineering-stack]] -- the three layers of any AI application stack: application development, model development, and infrastructure
- [[infrastructure]] -- bottom layer of the AI stack, covering model serving, data/compute management, and monitoring
- [[transformer-architecture]] -- dominant attention-based architecture for language-based foundation models, replacing seq2seq
- [[attention-mechanism]] -- lets a model weigh the importance of different input tokens via query, key, and value vectors
- [[seq2seq-architecture]] -- earlier encoder-decoder RNN architecture that the transformer was designed to replace
- [[mlp-module]] -- feedforward layers plus nonlinear activation that pair with attention inside a transformer block
- [[state-space-models]] -- alternative long-sequence architecture family (S4, H3, Mamba, Jamba) challenging the transformer
- [[model-size]] -- a foundation model's parameter count, its relationship to learning capacity, compute, and dataset size
- [[mixture-of-experts]] -- sparse model architecture where only a subset of expert parameters activate per token
- [[training-tokens]] -- token-based measurement of dataset and training scale, distinct from raw sample counts
- [[flop]] -- floating point operations as a standardized unit of training compute cost
- [[chinchilla-scaling-law]] -- rule for compute-optimal model size and dataset size given a fixed compute budget
- [[scaling-extrapolation]] -- predicting large-model hyperparameters by extrapolating from smaller models
- [[scaling-bottlenecks]] -- data and electricity limits on continued foundation-model scaling
- [[inverse-scaling]] -- cases where larger models perform worse than smaller ones
- [[multilingual-models]] -- why general-purpose foundation models underperform on non-English languages, especially low-resource ones
- [[supervised-finetuning]] -- first post-training step, finetunes on instruction data to optimize for conversation over completion
- [[preference-finetuning]] -- second post-training step, aligns model outputs with human preference via RL techniques like RLHF and DPO
- [[reward-model]] -- scores (prompt, response) pairs to guide preference finetuning, trained on comparison data
- [[sampling]] -- how a model constructs outputs from computed probabilities, the basis of AI's probabilistic behavior
- [[greedy-sampling]] -- always picking the highest-probability outcome; works for classification, boring for language models
- [[best-of-n-sampling]] -- generating multiple outputs and selecting the reward-model-scored best, sometimes replacing RL entirely
- [[logits]] -- raw unnormalized per-token scores a language model outputs before softmax
- [[softmax]] -- converts logits into a probability distribution over the vocabulary
- [[temperature]] -- adjusts logits before softmax to trade off creativity vs. predictability in sampling
- [[logprobs]] -- log-scale token probabilities returned by model providers, useful for classification and debugging
- [[top-k-sampling]] -- restricts softmax to the top-k highest-logit tokens to cut computation
- [[top-p-sampling]] -- nucleus sampling, dynamically selects the smallest token set whose cumulative probability exceeds p
- [[stopping-condition]] -- determines when autoregressive generation halts, trading latency/cost against output completeness
- [[test-time-compute]] -- spending extra inference-time computation, e.g. sampling multiple outputs and taking the most frequent, to improve model outputs
- [[supervised-finetuning]] -- first post-training step, finetunes on demonstration data to optimize for conversation over completion (updated with demonstration-data detail and cost figures)
- [[test-time-compute]] -- spending extra inference-time computation, e.g. sampling multiple outputs and selecting the best via logprobs, a reward model, or heuristics, to improve model outputs
- [[probabilistic-nature-of-ai]] -- why AI models sample answers rather than returning fixed ones, and how that causes inconsistency and hallucination
- [[inconsistency]] -- when a model gives different responses to the same or slightly different prompts
- [[hallucination]] -- when a model gives a response ungrounded in facts, and the two leading hypotheses for why
- [[training-data]] -- the data a model is trained on, why gaps in it limit capability, and the difficulty of collecting enough of it

- [[github-copilot]] -- code completion tool, one of the earliest production successes of foundation models

- [[photoroom]] -- example of a startup product that could have been a Google Photos feature; author is an investor
- [[grammarly]] -- writing assistant app that finetunes a model for fluency, coherence, and clarity
- [[alphafold]] -- DeepMind's protein structure prediction model, trained on ~100,000 known protein sequences and structures
- [[bionemo]] -- NVIDIA's domain-specific model for biomolecular drug-discovery data
- [[med-palm2]] -- Google's LLM combined with medical data for medical query answering
- [[llama-2]] -- Meta's transformer model family used to illustrate transformer dimension sizing
- [[llama-3]] -- Meta's transformer model family with larger vocabulary and context length than Llama 2
- [[mixtral-8x7b]] -- Mistral's 8-expert mixture-of-experts model, worked example of MoE parameter/compute counting
- [[common-crawl]] -- large public web-scrape dataset heavily skewed toward English, used to train most disclosed foundation models
- [[rlhf]] -- reinforcement learning from human feedback, a preference-finetuning technique used by GPT-3.5 and Llama 2
- [[laion]] -- non-profit that crowdsourced volunteer-labeled conversational data, with skewed labeler demographics
- [[instructgpt]] -- OpenAI model finetuned on demonstration data, the book's worked example of supervised finetuning
